# 项目说明

## 1. 项目背景

英科医疗需要持续关注一次性手套、医疗耗材、原材料、市场和竞品等相关信息。系统先通过可扩展的 RSS 源和关键词组收集候选新闻，再由 DeepSeek 判断业务相关性并完成摘要、分类、影响与风险分析，最终形成可筛选、可追溯的企业情报日报。

## 2. 建设目标

- 降低人工搜索和重复浏览新闻的工作量。
- 让 RSS 源和关键词能够由业务人员持续扩充。
- 保证每次采集范围明确、失败可追踪、数据可去重。
- 同时支持每日自动运行和人工即时运行。
- 为后续智能分析模块提供稳定的数据入口。
- 将关键词误命中的候选文章与真正的企业业务情报分开保存。
- 为管理层形成按日期、关键词分类分别汇总的风险日报和建议动作。

## 3. 当前范围

### 已实现

- RSS 源的新增、编辑、启停和归档。
- 关键词组的新增、编辑、启停和归档。
- 根据主题词、业务信号词、排除词和回溯天数自动生成搜索查询表达式，并按 RSS 源语言拆分中英文词。
- RSS、Atom Feed 下载与解析。
- 标题和摘要关键词匹配。
- 增量时间窗、独立游标及失败重试语义。
- URL 与文章指纹去重。
- 去重文章的多 RSS 来源追踪。
- RSS GUID、语言、国家、原始分类及标准发布方存储。
- 文章存储、筛选和采集日志。
- 每日定时采集与手动触发。
- CCTQ 的 GPT-5.4 mini 通过 OpenAI Responses API 兼容接口和内置网页搜索直接读取候选链接正文，项目不下载或解析新闻 HTML。
- 网页搜索证据校验、正文完整性门控、哈希与失败日志。
- 全文失败错误分类、最多 3 次指数退避、最终失败状态及人工重试/忽略。
- DeepSeek 基于 `full_text` 的独立相关性审核及主/次业务分类。
- 仅对通过阈值的真相关文章执行摘要、分类复核和影响分析。
- 风险分数、风险因素、机会与建议动作提取。
- 按日期与单一关键词分类生成并存储情报日报。
- AI 批次、失败、模型、Prompt 版本与 Token 用量日志。
- 错误数据、历史数据和全部采集数据的分层清理、执行确认与自动备份。
- 采集后自动分析与自动日报开关。

### 暂未实现

- 指定日期范围的历史补采。
- 邮件、企业微信、钉钉等消息推送。
- OpenAI 网页搜索无法读取的登录墙、付费墙和受限网页兜底。
- 用户、角色、权限和审计。
- MySQL 高可用、任务队列及生产级部署。

## 4. 核心业务规则

1. 每个“RSS 源 × 关键词组”维护独立采集游标。
2. 新关键词首次成功采集范围为其配置的北京时间回溯天数至任务开始时间。
3. 后续范围为上次成功采集时间至本次任务开始时间；若游标早于配置回溯范围，Google News 请求会自动扩展回溯天数以覆盖游标。
4. 单个组合采集失败时不推进游标，下次继续补采。
5. 新闻发布时间必须位于本次时间窗内。
6. 标题或摘要至少命中一个正文匹配词才允许入库。
7. 查询表达式由必需的主题词组、可选业务信号词组、排除词和 Google News 回溯窗口组成；主题词组内使用 `OR`，主题词组与信号词组之间使用显式 `AND`，并限制为 200 字符以内。实际采集按来源语言切片，中文词只进入 `zh-*` 源，英文词只进入 `en-*` 源。
8. 文章通过规范化 URL 和“标题 + 发布方 + 发布日期”指纹去重。
9. 同一时刻只允许执行一个采集任务。
10. 重复文章不重复插入，但每个 RSS 来源都记录为独立来源观测。
11. RSS 候选文章的链接、标题和发布方交给 CCTQ 的 GPT-5.4 mini 内置网页搜索读取；必须有已完成的 `web_search_call` 且正文完整才保存，失败时不使用标题或 RSS 摘要代替。
12. 马来西亚新闻除通用区域搜索外，还使用 The Star 和 The Edge 站点限定 Google News RSS。
13. 第一次模型调用判断相关性并给出主/次分类；模型判为相关且分数达到阈值后才写入业务情报库。
14. 无关文章只保留审核理由、审核分类与证据，不执行摘要、影响和风险分析。
15. 第二次模型调用只处理已进入业务情报库的文章，并生成后续分析字段。
16. 日报只能使用指定北京时间日期内、业务分析成功且命中所选关键词分类的文章；“贸易政策”和“关税调整”等分类分别生成。
17. 日报风险分数不能低于所选文章中的最高风险分数，所有结构化条目必须引用有效来源文章，并由后端附加发布方与原文链接。

## 5. 验收要点

- 修改主题词、业务信号、排除词或回溯天数后，页面通过后端查询模块实时生成正确表达式。
- 搜索型 RSS 地址正确替换并编码 `{query}`。
- 首次和后续采集使用正确时间窗。
- 失败任务有错误记录且不推进对应游标。
- 重复执行不会产生重复文章。
- 日志能够查看读取、时间窗外、命中、新增和错误数量。
- 拳击手套、体育、软件、加密货币等关键词误命中能够被判为业务无关。
- Google News 候选能够保存 DeepSeek 联网读取到的最终链接和正文。
- 全文、相关性和业务分析阶段的错误可分别在处理日志中追踪。
- 两次 AI 返回内容必须分别通过固定 JSON Schema 校验。
- 日报按日期和关键词分类选择文章，不同关键词分类互不混合，保存后可重新打开并追溯原始新闻链接。

## 6. 后续建议

1. 增加可选择开始和结束日期的历史补采任务。
2. 将采集调度迁移到独立 worker 和任务队列。
3. 增加其他合规的模型原生网页读取适配器和来源可信度配置。
4. 增加人工复核、Prompt 效果评估集和模型成本看板。
5. 增加用户权限、通知订阅和数据导出。
6. 完善 MySQL 备份恢复与高可用部署，并增加容器化与持续集成。

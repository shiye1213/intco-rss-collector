# 项目说明

## 1. 项目背景

英科医疗需要持续关注一次性手套、医疗耗材、原材料、市场和竞品等相关信息。当前阶段先建设信息采集模块，通过可扩展的 RSS 源和关键词组自动收集新闻，为后续分类、摘要、分析和推送提供结构化数据。

## 2. 建设目标

- 降低人工搜索和重复浏览新闻的工作量。
- 让 RSS 源和关键词能够由业务人员持续扩充。
- 保证每次采集范围明确、失败可追踪、数据可去重。
- 同时支持每日自动运行和人工即时运行。
- 为后续智能分析模块提供稳定的数据入口。

## 3. 当前范围

### 已实现

- RSS 源的新增、编辑、启停和归档。
- 关键词组的新增、编辑、启停和归档。
- 根据正文匹配词自动生成搜索查询表达式。
- RSS、Atom Feed 下载与解析。
- 标题和摘要关键词匹配。
- 增量时间窗、独立游标及失败重试语义。
- URL 与文章指纹去重。
- 去重文章的多 RSS 来源追踪。
- RSS GUID、语言、国家、原始分类及标准发布方存储。
- 文章存储、筛选和采集日志。
- 每日定时采集与手动触发。

### 暂未实现

- 指定日期范围的历史补采。
- 新闻网页正文抓取及 Google News 最终原文链接解析。
- AI 摘要、分类、情感和趋势分析。
- 邮件、企业微信、钉钉等消息推送。
- 用户、角色、权限和审计。
- PostgreSQL、任务队列及生产级高可用部署。

## 4. 核心业务规则

1. 每个“RSS 源 × 关键词组”维护独立采集游标。
2. 首次成功采集范围为北京时间当天 00:00 至任务开始时间。
3. 后续范围为上次成功采集时间至本次任务开始时间。
4. 单个组合采集失败时不推进游标，下次继续补采。
5. 新闻发布时间必须位于本次时间窗内。
6. 标题或摘要至少命中一个正文匹配词才允许入库。
7. 查询表达式只由匹配词通过 `OR` 组合，不自动追加领域词或排除词。
8. 文章通过规范化 URL 和“标题 + 发布方 + 发布日期”指纹去重。
9. 同一时刻只允许执行一个采集任务。
10. 重复文章不重复插入，但每个 RSS 来源都记录为独立来源观测。

## 5. 验收要点

- 新增匹配词后页面实时生成正确查询表达式。
- 搜索型 RSS 地址正确替换并编码 `{query}`。
- 首次和后续采集使用正确时间窗。
- 失败任务有错误记录且不推进对应游标。
- 重复执行不会产生重复文章。
- 日志能够查看读取、时间窗外、命中、新增和错误数量。

## 6. 后续建议

1. 增加可选择开始和结束日期的历史补采任务。
2. 将采集调度迁移到独立 worker 和任务队列。
3. 增加全文抓取、正文清洗和来源可信度配置。
4. 接入大模型完成摘要、分类和企业相关性评分。
5. 增加用户权限、通知订阅和数据导出。
6. 迁移 PostgreSQL，并增加容器化与持续集成。

把“我觉得能用”变成可重复验证

你将会运行 pytest、读懂测试结构、使用临时数据库和假依赖，并建立可复现的调试循环。

1. 一个测试由准备、执行、断言组成

def test_keyword_query_uses_short_root_term():
    query = build_keyword_query(
        ["关税"],
        context_terms=["政策"],
        lookback_days=30,
    )

    assert '"关税"' in query
    assert len(query) <= 200
  • Arrange：准备输入。
  • Act：调用真实代码。
  • Assert：断言可观察结果。

2. 运行测试

# 全部测试
.venv\Scripts\python.exe -m pytest -q

# 单个文件
.venv\Scripts\python.exe -m pytest tests/test_collector.py -q

# 单个测试
.venv\Scripts\python.exe -m pytest tests/test_collector.py::test_name -q

先运行最小相关测试获得快速反馈，再运行完整测试检查意外影响。

3. tmp_path 保护真实数据

def test_database(tmp_path):
    database = Database(tmp_path / "test.db")
    database.initialize()

tmp_path 为每个测试提供临时目录。测试不会修改 data/rss_collector.db，结束后可以清理。

4. Mock/Fake 隔离网络和费用

模型、RSS 和时间都可能不稳定。测试使用可控替身：

class FakeContentReader:
    configured = True

    def read(self, article):
        return ContentDocument(
            requested_url=article.urls[0],
            final_url=article.urls[0],
            full_text="固定测试正文",
            content_hash="fixed-test-hash",
            content_chars=6,
            http_status=200,
            content_type="text/html",
        )

这不是“假装测试”，而是精确验证我们自己的流程。真实服务兼容性应另做少量集成测试。

5. 调试先建立红灯

  1. 把用户描述转成可自动检查的结果。
  2. 运行并确认它真的失败。
  3. 列出多个可证伪假设。
  4. 一次只改变一个变量。
  5. 修复后先让原红灯变绿，再跑完整测试。

“页面没看到关键词”的红灯不是“程序没崩”，而是断言 API 中某个关键词的 match_terms == ["关税"]。

6. 项目的关键安全边界

  • 密钥：放在 .env，不能提交 Git，也不能打印。
  • SQL：使用参数绑定，不拼接输入。
  • URL：只允许公开 HTTP/HTTPS，阻止 SSRF。
  • 删除：先预览、备份、确认，并拒绝任务运行中清理。
  • 外部调用：设置超时、限制输出、分类错误和控制重试。

7. 动手练习

  1. 运行完整测试并记录通过数量。
  2. 打开 tests/test_collector.py，找到一个使用 tmp_path 的测试。
  3. 故意把该测试的一条预期改错，观察失败信息，然后立即恢复；不要修改真实数据库。

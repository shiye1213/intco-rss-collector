看懂项目里的“机器图纸”和错误通道

你将理解模块、类、对象、dataclass、Protocol 和异常，并看懂为什么正文读取器可以被替换。

1. 模块与 import

一个 Python 文件就是一个模块。app/main.py 可以使用其他模块公开的名字：

from .database import Database
from .llm import DeepSeekClient, OpenAIWebContentReader

开头的点表示“从同一个 app 包中导入”。阅读时先问：这个名字在哪里定义？再跳到对应文件，不要猜。

2. 类是图纸，对象是机器

class Database:
    def __init__(self, path: Path) -> None:
        self.path = path

database = Database(Path("data/rss_collector.db"))

class Database 定义图纸；最后一行创建具体对象。self.path 是这台对象自己的状态，方法则是它能执行的动作。

3. dataclass：只想清楚描述数据

app/content.py 使用 dataclass 表示文章引用和读取结果：

@dataclass(frozen=True)
class ArticleReference:
    title: str
    publisher: str
    urls: tuple[str, ...]

@dataclass(frozen=True)
class ContentDocument:
    requested_url: str
    final_url: str
    full_text: str
    content_hash: str
    content_chars: int
    # 还包含 HTTP 状态、内容类型和提取器名称

@dataclass 自动生成初始化等重复代码；frozen=True 表示创建后不应修改。它适合“数据包”，而不是复杂业务机器。

4. Protocol：约定能力，不绑定厂家

class ArticleContentReader(Protocol):
    @property
    def configured(self) -> bool: ...

    def read(self, article: ArticleReference) -> ContentDocument: ...

这个协议只要求正文读取器具备 configured 和 read()。真正实现可以是 GPT 网页搜索，也可以是测试中的假读取器。业务层只依赖“能做什么”，不依赖“由谁做”。

5. 异常：失败也要走清晰通道

class ContentFetchError(RuntimeError):
    def __init__(
        self,
        message: str,
        *,
        failure_kind: str,
        retryable: bool,
    ):
        super().__init__(message)
        self.failure_kind = failure_kind
        self.retryable = retryable

try:
    document = reader.read(article)
except ContentFetchError as error:
    save_failure(error.failure_kind, error.retryable)

raise 抛出异常，try/except 捕获异常。本项目不仅保存文字错误，还保存失败类型和是否可重试，才能决定后续动作。

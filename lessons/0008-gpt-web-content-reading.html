看懂 GPT 如何从链接得到可追溯正文

你将理解 CCTQ/OpenAI Responses 请求、强制网页搜索、结果解析、安全校验和失败分类。

1. RSS 候选不等于正文

RSS 常只有标题、短摘要和 Google News 跳转链接。相关性判断需要原文证据，因此流程是：

候选文章标题、发布方、多个 URL
GPT 网页搜索打开候选或规范页面
结构化正文正文、最终 URL、内容哈希
SQLite 保存后续分析可复用

2. ArticleContentReader 是边界

ArticleAnalysisManager 只调用：

document = content_reader.read(
    ArticleReference(
        title=article["title"],
        publisher=article["publisher"],
        urls=tuple(urls),
    )
)

具体实现 OpenAIWebContentReader 可以变化，分析管理器不用知道 HTTP 请求细节。

3. Responses API 请求的核心

{
  "model": "gpt-5.4-mini",
  "tools": [{"type": "web_search"}],
  "tool_choice": "required",
  "include": ["web_search_call.action.sources"],
  "store": false
}
  • web_search：允许模型搜索和打开网页。
  • tool_choice: required：不能只凭标题和模型记忆回答。
  • include：要求服务返回搜索来源，用来确认网页工具实际执行。
  • store: false：请求不要求服务端持久保存。

提示词明确要求：只保存真正读到的页面正文，不根据标题、摘要或背景知识重构文章。

4. 结果必须同时通过多项检查

  • HTTP 请求成功。
  • 响应 JSON 结构正确。
  • 网页搜索调用已经完成。
  • 模型返回 success=true。
  • 正文长度达到最低要求。
  • 最终 URL 合法，正文可生成稳定内容哈希。

任一步失败都会生成 ContentFetchError，携带 failure_kind 和 retryable。当前持久化对象保存正文、最终地址、哈希、字符数和 HTTP 元数据；不会把模型返回的完整搜索来源列表写入数据库。

5. URL 安全不是可选项

validate_public_http_url() 只允许公开的 HTTP/HTTPS 地址，阻止模型读取本机、内网或其他危险地址。这类防护叫 SSRF 防护。

6. 为什么正文要保存？

  • 相关性审核和业务分析复用同一份证据。
  • 失败重试不必重复已经成功的收费调用。
  • 正文哈希能判断旧审核是否仍适用于新内容。
  • 用户可以追溯模型判断依据。

Capstone · 2–4 hours

独立增加“关键词政策优先级”功能

这一课不是阅读练习，而是把数据库、API、前端和测试连接起来。完成后，你就经历了一次真实的端到端开发。

注意：下面是待你实现的综合任务，不是当前项目已经存在的功能。先建立分支和测试，不要直接修改正式数据库。

1. 先写清楚需求

每个关键词组增加政策优先级：

  • 允许值：low、medium、high。
  • 旧关键词默认 medium。
  • 新增和编辑弹窗可以选择。
  • 关键词列表显示中文标签：低、中、高。
  • API 拒绝其他值并返回 422。
  • 暂时不改变采集顺序，避免扩大需求。

2. 画出改动链

SQLite增加 priority 字段与迁移
Pydantic/API校验、读写与响应
前端表单选择和列表标签
pytest旧库升级与接口行为

4. 第二步：数据库迁移

if "priority" not in keyword_columns:
    connection.execute(
        """
        ALTER TABLE keywords
        ADD COLUMN priority TEXT NOT NULL DEFAULT 'medium'
        """
    )

同时修改建表 SQL、查询返回、创建和更新方法。所有 SQL 参数数量必须同步调整。

5. 第三步：请求模型

from typing import Literal

class KeywordPayload(KeywordQueryPayload):
    priority: Literal["low", "medium", "high"] = "medium"

Literal 让 Pydantic 自动拒绝非法值。然后把字段传给 create_keyword() 和 update_keyword()。

6. 第四步：前端表单和展示

  1. 在 static/index.html 的关键词弹窗增加 select。
  2. openKeywordDialog() 回填现有优先级。
  3. saveKeyword() 把 priority 放进 JSON。
  4. renderKeywords() 显示优先级标签。
  5. 使用 escapeHtml() 处理显示内容。

7. 第五步：验证完整路径

  1. 运行单个迁移测试。
  2. 运行关键词 API 测试。
  3. 运行全部 pytest。
  4. 启动本地应用，新增 high 关键词。
  5. 刷新页面，确认仍为 high。
  6. 检查 SQLite 记录。
  7. 确认 .env 和数据库文件没有进入 Git。

8. 完成定义

只有同时满足以下条件才算完成：

  • 新数据库和旧数据库都能启动。
  • API 对合法与非法输入行为明确。
  • 保存后刷新页面数据不丢失。
  • 完整测试通过。
  • Git diff 中没有密钥、数据库和无关文件。
  • 你能用自己的话解释每个文件为什么要改。

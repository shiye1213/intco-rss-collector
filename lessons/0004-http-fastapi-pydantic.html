从一个 URL 读懂前后端的契约

你将能根据请求方法和路径找到后端函数，并理解 Pydantic 如何在业务代码之前挡住错误输入。

1. HTTP 请求由什么组成？

请求 Request

  • 方法：GET、POST、PUT、DELETE
  • 路径：/api/keywords
  • 请求头：内容类型、认证等
  • 请求体：通常是 JSON

响应 Response

  • 状态码：200、201、202、404、422、500
  • 响应头
  • 响应体：本项目通常是 JSON

GET 通常读取，POST 通常创建或启动，PUT 更新完整资源，DELETE 删除或归档。它们是约定，不是数据库命令。

2. FastAPI 把路径绑定到函数

@app.get("/api/keywords")
def list_keywords():
    return {"items": database.get_keywords()}

@app.post("/api/keywords/preview")
def preview_keyword_query(payload: KeywordQueryPayload):
    return {"query": payload.build_query()}

装饰器 @app.get(...) 像门牌，下面的函数是窗口工作人员。路径参数、查询参数和请求体会被 FastAPI 自动传入。

3. Pydantic 是入口质检员

app/main.py 中的请求模型声明外部数据应长什么样：

class KeywordQueryPayload(BaseModel):
    match_terms: list[str]
    context_terms: list[str] = []
    exclude_terms: list[str] = []
    lookback_days: int = Field(default=30, ge=1, le=365)

如果天数是 0、500 或无法变成整数，Pydantic 在进入业务逻辑前返回 422。这样数据库和查询构建器可以假设输入已经过基本检查。

4. 状态码告诉调用方结果类型

  • 200 OK：读取或更新成功。
  • 201 Created：资源创建成功。
  • 202 Accepted：耗时任务已接收，但还没有完成。
  • 404 Not Found：资源不存在。
  • 409 Conflict：当前状态冲突，例如已有任务运行。
  • 422 Unprocessable Entity：请求数据不符合模型。

5. 一次安全的本地调用

应用运行时，在 PowerShell 执行下面命令不会触发采集或收费模型：

Invoke-RestMethod http://127.0.0.1:8000/api/status

你会看到浏览器首页所需的文章数、来源数、关键词数和任务状态。浏览器只是把同一份 JSON 画成卡片。

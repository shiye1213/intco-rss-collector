理解项目为什么重启后还能记住一切

你将读懂表、行、主键、外键、SQL、事务和迁移，并理解刚刚遇到的“代码改了但页面没变”。

1. SQLite 是一个数据库文件

本项目把数据保存在 data/rss_collector.db。Python 进程结束后，文件仍然存在，所以新闻、关键词和任务记录不会丢失。

表 Table

结构固定的一类数据，例如 articles 或 keywords。

行 Row

表中的一条具体记录，例如某篇新闻。

主键 Primary Key

唯一识别一行的 ID。

外键 Foreign Key

保存另一张表的 ID，建立关系。

2. 用 SQL 对数据库说话

SELECT id, name, active
FROM keywords
WHERE archived = 0
ORDER BY name;

SELECT 选择字段，FROM 指定表，WHERE 过滤行，ORDER BY 排序。写入则使用 INSERT、UPDATE 和 DELETE。

3. 永远绑定参数，不拼接用户输入

connection.execute(
    "SELECT * FROM keywords WHERE id = ?",
    (keyword_id,),
)

问号是参数占位符。SQLite 驱动负责安全传值，也能避免引号错误和 SQL 注入。不要写成 f"... WHERE id = {keyword_id}"。

4. 事务：一组修改要么全成功，要么全失败

with database.connect() as connection:
    connection.execute("UPDATE ...")
    connection.execute("INSERT ...")

上下文正常结束时提交；中途抛出异常时回滚。这样不会出现“文章写入了，但关键词关系没写入”的半成品。

5. 迁移：代码结构变了，旧数据库也要跟上

修改 Python 中的默认关键词，不等于修改已经存在的数据库行。INSERT OR IGNORE 遇到同名记录会跳过，这正是“代码已经变成关税，页面仍显示旧词”的原因。

if "new_column" not in existing_columns:
    connection.execute(
        "ALTER TABLE keywords ADD COLUMN new_column TEXT"
    )

迁移必须保护用户数据。本项目对旧关税默认值采用条件升级：只有记录仍与旧默认值完全一致才替换；用户改过就保留。

6. Repository：把 SQL 集中起来

Database.get_keywords()、create_keyword() 和 update_keyword() 把 SQL 封装成业务可以理解的方法。路由不需要到处复制 SQL。
